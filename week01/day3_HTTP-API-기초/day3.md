# 1. 네트워크 핵심 개념
## 1. 네트워크
- 인터넷 : 전 세계 수많은 네트워크를 연결한 거대한 네트워크
- 네트워크 : 두 대 이상의 컴퓨터를 연결하여 데이터를 공유할 수 있돌고 연결된 통신 시스템
    1. 클라이언트 : 서비스를 요청하는 컴퓨터 혹은 사용자
    2. 서버 : 클라이언트의 요청에 응답하여 서비스를 제공하는 컴퓨터
    3. 통신 프로토콜 : 네트워크 상에서 데이터를 교환하기 위한 규칙과 절차
## 2. IP 주소
- 클라이언트와 섭서는 서로의 위치를 찾아 통신할 수 있을까?
- IP 주소 : 네트워크 상에서 데이터 패킷의 발신지와 목적지를 식별하는 고유 주소

- IPv4 : 4개의 옥텟(8비트)로 구성, 각 옥텟은 0~255 범위의 10진수
    - 네트워크 ID와 해당 네트워크 내의 개별 호스트를 구분하는 호스트ID로 구분 가능
    - 한계 : 주소 부족
- IPv6 : 128비트 주소 체계, 8개의 16비트 숫자
- nslookup [옵셥] [도메인이름] 명령어로 IP 주소 확인 가능

##  3. DNS
- IP 주소은 길고 복잡해서 사람들이 기억하기 어려움, 주소가 변경될 수도 있음
- 도메인 이름 : IP 주소 대신 기억하기 쉬운 문자열
- DNS : 도메인 이름과 IP 주소 간의 변환을 해주는 시스템
- 웹 브라우저는 URL이 입력되면 먼저 DNS 서버에 요청해 IP 주소를 받음

## 4. PORT 번호
- 같은 기기에 둘 이상의 기기가 연결되는 경우 어떻게 통신될까?
- 네트워크에서 기기의 특정 애플리케이션나 서비스에 연결할 수 있도록 식별하는 번호
- 범위 : 0 ~ 65535
- IP주소:포트번호 로 표현
- 사용중인 포트는 중복해서 사용할 수 없음

## 5. 네트워크의 종류
- 범위에 따른 구분
    - PAN : 개인의 장치들 간의 연결
    - LAN : 사무실, 학교 등 제한된 지역 내
    - MAN : 도시나 대도시 지역
    - WAN : 넓은 지리적 범위 (인터넷, 글로벌 기업 네트워크)
## 6. 네트워크 토폴로지와 통신 방식
- 토폴로지 : 네트워크의 요소들(링크, 노드 등)을 물리적으로 연결한 구조 및 연결 방식
    - 버스 : 모든 장치가 하나의 중앙 케이블(백본)에 연결
    - 스타 : 모든 장치가 중앙 허브 또는 스위치에 연결
    - 링 : 각 장치가 두 인접 장치와 연결
    - 메시 : 모든 장치가 서로 직접 연결
- 통신 방식
    - 유니캐스트 : 1:1로 통신 (HTTP)
    - 멀티캐스트 : 1:N로 통신, 특정 그룹의 수신자에게만
    - 브로드캐스트 : 한 송신자가 네트워크 내 모든 대상에게 데이터를 전송
## 7. TCP/IP 프로토콜
- IP 프로토콜 : 데이터를 패킷 단위로 전송
    - 신뢰성 문제 : 단순히 전달, 오류 제어 기능 없음 (순서, 재전송)
- TCP/IP : 데이터가 정확한 목적지에 도달할 수 있도록 하는 통신 규악
    - 인터넷의 기본 프로토콜 스택
- 계층
    - 4계층 응용 : 응용 프로그램 데이터 통신 (HTTP, FTP ...)
    - 3계층 전송 : 데이터 저송의 신뢰성 및 순서 보장 (TCP, UCP)
    - 2계층 인터넷 : 패킷 주소 지정 및 라우팅 (IP)
    - 1계층 네트워크 액세스 : 물리적 네트워크와 데이터 전송 (이더넷, 와이파이)

## 8. TCP와 UDP
- 전송 계층
- 데이터 전송 규약을 정의
- TCP
    - 연결형 : 데이터 전송 전에 수신자와 송신자 사이의 연결을 설정
    - 흐름 및 혼잡 제어, 순서 보장
    - 신뢰성 but 느림
    - 데이터의 신뢰성이 중요할 때 사용
    - 3-way handshake : client:SYN -> server:SYN/ACK -> client:ACK
- UDP
    - 비연결형
    - 빠름 but 낮은 신뢰성
    - 빠른 속도가 중요한 실시간 서비스
# 2. HTPP 프로토콜과 RESTful
## 1. 브라우저의 동작 원리
- 브라우저 주소창에 URL 을 입력
1. DNS 서버 요청 ->  IP 주소 응답
2. 브라우저 HTTP 요청 메시지 생성 : 응용 계층에서
3. TCP/IP 패킷 생성 : 캡슐화 == 포장
    - 전송/인터넷 계층 : IP패킷(출발지와 도착지 정보)으로 감싸기
    - 네트워크 액세스 계층 : (이더넷)프레임으로 감싸기
    - 최종적으로 프레임으로 캡슐화됨
4. 요청 패킷 전달
5. TCP/IP 패킷 해제 : 역캡슐화
6. 서버의 응답 패킷 전달
7. 브라우저의 도움을 받아 응답(홈페이지 화면)을 띄움

## 2. HTTP 프로토콜과 핵심 특징
- 프로토콜 : 네트워크 통신에서 데이터를 교환하기 위한 규칙과 표준
    1. 단편화/재합성
    2. 캡슐화
    3. 연결/흐름/오류 제어
    4. 순서 결정
    5. 주소 설정
    6. 동기화/다중화
- HTTP : 응용 계층의 프로토콜
    - 클라이언트-서버 간 데이터가 교환되는 방식에 대한 규약
    - 거의 모든 형태의 데이터 전송 가능 : json, 영상, 오디오 등...
    - **무상태성과 비연결성**
- 무상태성 : 서버가 클라이언트의 상태를 보존하지 않음
    - 각 요청은 독립적
    - 서버의 확장성 : 여러 대의 서버 중 아무데나 요청 가능
- 비연결성 : 클라이언트-서버 간 연결을 유지 하지 않음
    - 요청 -> 응답 -> 바로 연결 종료
    - 서버 자원의 효율화 : 바로 다른 요청 응답 처리 시작
- HTTPS : HTTP의 보안 버전
    - 데이터 암호화 : 요청과 응답이 암호화됨
    - TLS/SSL 프로토콜 사용

## 3. HTTP 메시지와 HTTP 메서드
- HTTP 메시지 : 데이터 전송 형식을 규정
    - 시작 라인, 헤더, 공백, 본문
- HTTP 메서드 : 클라이언트가 서버에게 수행할 작업의 종류를 지시하는 명령어
    - CRUD 작업 : create, read, update, delete 작업을 표현
- GET : 데이터를 조회
    - 요청 Body X
    - 요청 URL에 쿼리 파라미터 포함 가능
- POST : 서버에 데이터를 전송하여 새로운 데이터를 생성
    - 요청 Body에 데이터 포함
    - 서버의 상태를 변경함
- PUT : 서버에 데이터를 전송하여 리소스를 완전히 대체
    - 요청 Body에 데이터 포함
- PATCH : 서버에 데이터를 전송하여 리소스를 일부 대체
    - 요청 Body에 데이터 포함
- DELETE : 서버에서 특정 리소스를 삭제
    - 요청 Body 없음
## 4. HTTP 요청 메시지/응답 메시지
- 차이 : 요청 메시지에서는 start line, 응답 메시지에서는 status line
- 요청 메시지
    1. start line (POST /api/data HTTP/1.1)
        1. HTTP 메서드
        2. 요청 타켓 (주로 url로 표현)
        3. HTTP 버전
    2. header
        - 요청에 대한 부가 정보 제공
        - 각 속성은 이름-값 쌍으로 설명
        - Content-Type : Body의 데이터 형식
    3. blank line : 구분을 위한 공백
    4. body
        - 클라이언트가 서버에 전달하는 실제 데이터
- 응답 메시지
    1. status line (HTTP/1.1 200 OK)
        1. HTTP 버전
        2. HTTP 상태 코드 : 요청의 상태에 대한 서버의 응답을 나타내는 3자리 숫자 코드
        3. 상태 메시지 : 응답 상태에 대한 설명
    2. header
    3. blank line
    4. body
## 5. HTTP 상태 코드
- 클라이언트 요청의 상태에 대한 서버의 응답을 나타내는 3자리 숫자 코드
- 1xx : 정보 응답, 요청을 처리 중
- 2xx : 성공
- 3xx : 리다이렉션, 요청 완료를 위해 추가 작업 필요
- 4xx : 클라이언트 요청 오류
- 5xx : 서버 오류
## 6. REST API 개요
- HTTP 프로토콜에 기반하여 REST 원칙을 따르는 API
- representational state transfer : HTTP 프로토콜에 기반하여 자원을 관리하는 방식
    - 자원을 이름으로 식별
    - 자원의 상태 정보를 주고 받음
- application programming interface : 시스템 간 상호작용을 위한 인터페이스
- 특징
    1. 클라이언트-서버 구조
    2. 무상태
    3. 응답 캐시 처리 가능
    4. 계층화 시스템 : 클라이언트는 서버를 직접 호출하지 않음
        - 다중 계층 허용 (로드 밸런싱, 보안, 암호화 등)
    5. 인터페이스 일관성 : 효율적인 아키텍처를 위한 일관된 인터페이스
    6. 코드 온 디멘트 : 서버는 실행 가능 코드 형태로 기능을 전송 가능
## 7. REST API의 구성 요소
1. 자원 - URI
    - 모든 자원에는 고유한 ID가 존재
    - DB의 엔티티나 정보의 단위
    - URI(uniform resource identifier) : 자원 식별자
        - 프로토콜, host ip, port, path, query parameters, ...
2. 행위 - HTTP 메서드
    - GET, POST, PUT, DELETE 등...
    - 자원에 대한 조작을 정의
    - 다른 HTTP 메서드, 동일한 url 가능
- 일관된 인터페이스
    - 리소스명은 명사형
    - 리소스에 대한 행위는 HTTP 메서드
    - URL 경로에는 소문자 사용
    - 계층 관계는 슬래시로 구분, 단 마지막 문자는 슬래시 사용하지 않음
    - 언더바 대신 하이픈 사용
3. 표현 - HTTP 메시지 페이로드
    - json & xml
    - json : 경량, 가독성 높음, 키/값 쌍의 집합 구조
- 자기 서술적 메시지 : 메시지가 자기 자신을 어떻게 처리해야 할지 전부 설명해야 함
- HATEOAS : 웹 페이지가 다른 페이지나 상태로 넘어갈 수 있도록 링크를 제공해야 함

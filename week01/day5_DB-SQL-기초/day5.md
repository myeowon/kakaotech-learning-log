# 1. 데이터베이스 개요
## 1. 데이터베이스 소개
- 한 조직 안에서 여러 사용자와 응용 프로그램에 **공동**
으로 사용하는 데이터들을 **통합**하여 **저장**하고 **운영**하는 데이터
- 필요성 : 파일 처리 시스템의 한계
    - 데이터 종속 : 데이터 구조가 바뀌면 응용 프로그램의 구조도 바뀌어야 함
    - 데이터 중복 : 응용 프로그램마다 데이터를 생성해 중복되는 데이터가 있을 수 있음
    - 무결성을 지킬 수 없음
- 특징
    1. 실시간 접근 가능
    2. 지속적인 변화로 최신 상태 유지
    3. 동시 공유
    4. 내용에 대한 참조 : 데이터가 저장된 물리적인 위치가 아닌 값을 가지고 검색할 수 있어야 함
## 2. 데이터베이스의 종류
### RDB(Relational)
- 관계형 모델을 기반 
- SQL을 이용해 데이터를 관리 (데이터의 구조가 일관적인 경우에 사용)
- 데이터를 행과 열을 가지는 테이블로 표현
- 데이터 간의 관계 -> 무결성 보장
- 스키마 정의 -> 안정성 보장
- MySQL, PostgreSQL, MariaDB
### NoSQL(Not only SQL)
- 데이터 간의 관계를 정의하지 않음, 데이터 유형의 제한이 없음
- 유연한 모델을 이용
- 데이터의 구조가 일관적이지 않고 자주 변경되는 경우에 적합
- mongoDB, redis, cassandra

## 3. 관계형 데이터베이스 만들기
- 테이블은 행과 열로 구성
- 속성 : 데이터의 특성을 나타내는 가장 논리적인 단위
- 튜플 : 속성이 모여 구성된 각각의 행
- 도메인 : 속성이 가질 수 있는 값의 집합
- SQL 작성 규칙
    - SQL 문법은 대문자로 작성하는 것을 권장
    - 테이블명, 속성명 등은 소문자로 작성하는 것을 권장
    - 이름에 여러 단어를 혼합하는 경우 "_"을 이용해 구분
    - "--" 을 이용해 주석
    - 명령어 끝에는 세미콜론을 작성
## 4. 데이터베이스 정의어
- SQL : 관계형 db를 활용하기 위해 사용하는 표준 언어
1. 데이터 정의어 (DDL) : 테이블과 같은 데이터 구조 정의
2. 데이터 조작어 (DML) : 데이터 조회 및 검색
3. 데이터 제어어 (DCL) : 데이터베이스에 접근하는 권한 관리

### 데이터 타입
- VARCHAR(n) : nBytes 크기의 가변 길이 문자열 데이터
- CHAR(n) : 고정 길이 문자열 데이터
- INT : 정수형 숫자 데이터 (4Bytes), (TINYINT, BIGINT)
- FLOAT : 4Bytes 크기의 부동 소수점 데이터 (DOUBLE 더 큰 크기)
- DECIMAL : 고정 소수점
- DATETIME : YYYY-MM-DD HH:MM:SS (DATE 날짜만, TIME 시간만)

# 2. 데이터베이스 구성하기
## 1. 제약 조건
- 테이블에 잘못된 데이터가 입력되는 것을 방지하기 위한 규칙
- 필드명 타입 **NOT NULL** : NULL 값 비허용
- 필드명 타입 **UNIGUE** : 중복되는 값 비허용
- 필드명 타입 **DEFAULT** 기본값 : 아무런 값을 지정하지 않으면 기본값으로 설정됨
- 필드명 타입 **CHECK** (조건) : 값의 범위를 제한하여 특정 값만 허용
- 제약 조건 이름 정의 : CONSTRAINT 제약조건이름 제약조건(UNIGUE, CHECK...)
## 2. 키
- 기본키 : 서로 다른 튜플을 유일하게 식별할 수 있는 기준이 되는 속성
    - 개체 무결성 : UNIGUE 제약 + NOT NULL 제약
    - 한 테이블 당 1개만 설정
    - 필드명 타입 **PRIMARY KEY**
- 외래키 : 다른 테이블의 기본키를 참조하는 속성
    - 참조 무결성 : NULL 혹은 참조되는 릴레이션의 기본키 값과 동일
    - 참조되는 테이블의 기본키에 없는 값은 지정 불가
    - **FOREIGN KEY** (참조할 속성) **REFERENCES** 참조되는 테이블(참조되는 속성)
## 3. 데이터 모델링
- 현실 세계의 데이터를 단순화, 추상화하여 표현한 모델
    - 개체 : 현실 세계의 개념이나 정보의 단위
    - 속성 : 개체에 대한 정보
    - 관계 : 개체 간의 연관성
- 과정 : 개념적 설계 -> 논리적 설계 -> 물리적 설계
    - 개념적 : 현실 세계를 추상적 개념을 표현
    - 논리적 : 데이터 구조(스키마)를 설계
    - 물리적 : 테이블을 저장할 구조를 설계
## 4. ER 다이어그램 (Peter Chen)
### ERD
- entity-relationship diagram : 개체와 관계 형태의 다이어그램으로 나타내는 것
- 표기법 : Peter Chen, IE
### Peter Chen
- 표현
    - 직사각형 : 개체 (개체명에 밑줄이 그어져있다면 기본키)
    - 타원 : 속성
    - 마름모 : 관계
    - 선 : 개체와 속성의 연결
- 관계
    - 1 -- 1 : 1:1 관계
    - 1 -- N : 1:N 관계
    - N -- M : N:M 관계
    - 하나의 데이터가 다른 테이블의 몇 개의 데이터와 관걔를 가지는지
## 5. ER 다이어그램 (IE)
### IE
- information engineering
- 키, 데이터 타입, 제약 조건을 표기
- 관계를 세부적으로 나타냄
### 까마귀발 (crow's foot) 표기법

- | | : 정확히 1
- 3 0 : 0 이상
- 3 | : 1 이상
